Step 1: Stage 1 Pre-Docker no_pytest_tests Filtering

Previously, candidates touching exclusively non-pytest directories (such as static type-checker fixtures under tests/typechecking/ or tests/mypy/) were launched inside Docker containers before being discarded by the adjudicator as not_minable:no_pytest_tests. This created unnecessary container build overhead and inconsistent record shapes.

Implementation:

  • Updated miner/candidates.py::not_minable_reason to inspect test_files during Stage 1 enumeration.
  • When every touched test file matches NON_PYTEST_TEST_DIRS, candidates are immediately stamped not_minable:no_pytest_tests before container creation.
  • All pre-filtered candidates carry explicit anchored = None and anchor = None, establishing clean record shape consistency across Stage 1 and Stage 2.
Impact: 72 out of 1,568 candidates (4.6% of the entire corpus) are now filtered out during Stage 1 enumeration without launching Docker.

Step 2: pydantic-core Wheel Caching, In-Container Alignment & 300s Timeout Guard

Starting with Pydantic commit 41f6776e6 (2025-11-10), pydantic-core became a uv workspace path dependency. In Docker container builds, RUN rm -rf /src deleted the source tree after installation, leaving pydantic_core unimportable and causing a 75% apparatus failure rate across 2025Q4?2026Q3.

Furthermore, even after fixing the build with uv export --no-editable, Pydantic's internal version check (version.py::_ensure_pydantic_core_version) raised a hard SystemError whenever the installed pydantic-core version differed from the candidate's exact pyproject.toml pin.

Implementation & Safeguards:

  1. Build-Time Wheel Caching (miner/quarters.py): During quarter image construction, all unique pydantic-core exact pins declared by candidates in that quarter are pre-downloaded into /opt/miner/wheels using pip download.
  2. In-Container Version Alignment (miner/runner.py): Before running pytest on a candidate, _align_core_pin installs the candidate's exact core_pin from /opt/miner/wheels into a user-writable target directory (/work/aligned-core) and prepends it to PYTHONPATH for all pytest executions.
  3. 300s Execution Timeout & Container Recovery Loop: Reduced the default pytest timeout from 1800s to 300s. If a candidate contains an infinite execution loop (such as c333d775's core schema recursion bug), ContainerLost is raised, apparatus: pytest timed out is recorded, and the runner automatically restarts a fresh container to continue processing subsequent candidates without halting the quarter.
# quarters.py Dockerfile layer:
RUN pip download --dest /opt/miner/wheels pydantic-core==2.41.1 && pip download --dest /opt/miner/wheels pydantic-core==2.41.5 ...

# runner.py in-container execution:
uv pip install --system --target /work/aligned-core --no-index --find-links /opt/miner/wheels pydantic-core==2.41.1
PYTHONPATH=/work/aligned-core:$PYTHONPATH pytest ...
