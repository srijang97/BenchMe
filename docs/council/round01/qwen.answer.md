POSITION: The oracle's job in this experiment is to make "solved" trustworthy in both directions. A weak oracle accepts incorrect patches (STING: 77%), and an overly strict oracle rejects valid alternatives (OpenAI: 35.5% of tests narrow) — both distort cost-per-solved, and the strict direction is the more dangerous for the commercial thesis because it systematically inflates the cost of whichever tier the oracle's style dislikes. Therefore: mandatory functional controls and requirement-anchored tests at entry, hardening only inside requirement space, alternative solutions as the counter-check on every hardening, mutation survival demoted to a reported diagnostic, and no LLM judge anywhere in the scoring path.

Q1: Entry requirements for decision-grade: (1) hidden behavior-asserting tests with a total requirement→test map — every requirement covered, every graded test mapped to a requirement or the regression contract; unmapped tests are excluded from grading. (2) Solve definition = target tests pass AND full regression passes AND no information-policy violation; regression failures are reported separately, but a solve that breaks the suite isn't a solve. (3) Four functional controls run and passing: baseline negative (pre-patch failure must be an assertion failure, not collection/import error — error2pass check), reference positive, regression, and at least one no-op or near-miss negative. (4) Determinism preflight: reference patch passes k=3 consecutive runs. (5) Harness-level sealing verified once per environment manifest (hidden tests absent, future git objects absent, network denial proven) — per BenchJack, red-team the environment, not each capsule. Nice-to-have: per-capsule adversarial probes, property-based tests, mutation suite. Entry is O2 + alternative control (see Q2), not O3.
